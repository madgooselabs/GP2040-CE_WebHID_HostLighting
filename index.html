Lighting

Click a swatch to paint it with the current color, then STAGE grid & commit. Pixels are always sent R,G,B; the board converts to its chain format.

Demo scenarios

Claim first so the board accepts staging. Static/pattern demos stage once and commit; animated ones stream until Stop. Rainbow, hue-cycle and index map ignore the picker; the rest use it. “Index map” tints each LED by its index so you can confirm ordering.

Targeted stage (addressing modes)

Uses the picker color. Runs (0/1) fill Count consecutive addresses; entry modes (4/5/6/7) stage one entry at Address (action is signed). This is what a spice2x host uses: button names → action, PLED/CASE/TURBO → kind, per-light index → light ordinal.
Reproduces hlp-spice2x hardware_lights phase 7 on a 2-light control: control red → that light cyan (entry overrides) → that light black (overrides) → cleared (both red). Fill in a real control's GpioAction and one of its light ordinals (from a page read or the bridge’s --list-lights).

Animation & brightness

Blank speed field = leave unchanged (0xFF); brightness step 0xFF = the saved step. SET_ANIMATION is vector-verified; SET_SPEED / SET_BRIGHTNESS / SET_PROFILE layouts come from the library source with no on-wire vector — watch the reply status. Profile writes flash and may pause replies ~200 ms.

Raw command

Payload goes at byte [3]. Generation/holder flags are OR'd in automatically once claimed.

Events & pages

bit 0 = STATE_CHANGED (the only event in 2.0)
1 state · 2 modes · 8 summary · 9 profiles · 10 pins · 11 keymap · 13 animations

Keyboard mapping

Count = number of codes (1–57). Codes are HID keyboard usages (page 0x07, e.g. 04=A). Needs “Allow hosts to change the keyboard mapping” enabled in firmware and an active matching profile, else status 1/3.

Reboot / input mode danger

Both reboot the board and may drop the lighting interface (recoverable only via the web configurator, a boot-button hold, or hotkeys). Each asks for confirmation. Source-only — no on-wire vector.
